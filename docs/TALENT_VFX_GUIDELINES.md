## 1. 제작 목표와 기준

차량과 차량 주변에 표시되는 경기 VFX는 **실사풍**으로 제작합니다. 이전 문서의 반실사·세미리얼 지침은 이번 지침으로 대체합니다.

실제 촬영 장면에 합성한 영화 VFX처럼 빛·물·공기·눈·전기·에너지의 질감과 움직임이 자연스러워야 합니다. 코드로 그린 단순한 도형이나 평면적인 장식처럼 보이는 표현은 피합니다. SF 에너지 효과도 실사 장면에 어울리는 재질과 광학적 표현을 지향합니다.

각 재능의 **완성된 발동 애니메이션을 사용자가 첨부**합니다. 해당 영상의 인상·색감·재질·움직임을 주요 시각 참고로 삼으세요.

기존 컨셉·색상·레이어 구성은 초기 참고일 뿐입니다. 이를 그대로 재현할 의무는 없으며, 영상과 재능의 의미를 바탕으로 더 좋은 방향을 제안해주세요.

기준의 우선순위:
1. 최신 사용자 지시와 승인
2. 최신 Game의 실제 재능 효과·발동 및 종료 조건
3. 첨부한 발동 애니메이션의 시각적 정체성
4. 아래 기존 컨셉 참고안

## 2. 발동 애니메이션을 경기 VFX로 옮기는 방법

발동 애니메이션과 경기 VFX는 역할이 다릅니다.

- 영상에서 재능을 대표하는 색·질감·운동 방향·리듬·핵심 형태를 추출합니다.
- 카메라 이동, 배경, 화면 전체 섬광, 영화적 과장은 작은 탑뷰 경기 화면에 맞게 재구성합니다.
- 컷인 영상을 차량 위에 축소해 재생하거나, 영상의 모든 요소를 그대로 옮기는 작업이 아닙니다.
- 재능을 구별하는 핵심 요소는 남기고 차량·트랙·주변 차량을 가리는 요소는 줄입니다.
- 영상의 시작 연출을 유지 구간에서 계속 반복하지 않습니다. 시작·유지·종료의 역할을 나눠 설계합니다.
- 실제 차량 크기 약 20~24 × 41~49px에서 읽히는 소수의 형태를 우선합니다.
- 차종마다 외형이 다르므로 특정 차체 표면에 정확히 맞아야만 성립하는 설계는 피합니다.

영상 확인 후 먼저 아래를 짧게 설명해주세요.
- 영상에서 가져올 핵심 시각 요소
- 경기 화면에 맞춰 변경하거나 생략할 요소
- 추천하는 시작·유지·종료 동작
- 기존 Studio 기능으로 가능한 범위와 필요한 아트 리소스

사용자와 방향을 합의한 뒤 구현합니다.

## 3. 역할 분담과 순서

- Claude: 영상 분석, 연출 기획, Studio 제작·구현, 승인 후 전달 package 생성.
- GPT: 필요한 PNG 아트 리소스 제작.
- Game GPT Codex: Game 연결, 실제 경기에서의 동작·성능 확인.
- 사용자: 기획과 최종 시각 승인.

재능 하나씩 진행합니다.
영상·컨셉 확인 → 연출 제안 → 사용자 합의 → 필요한 아트 요청 → Studio 시안 → 시각 확인·수정 → package 생성 → Game 적용.

15종 일괄 구현이나 미리 모든 리소스를 제작하지 마세요.

## 4. 완료된 재능 — 수정하지 않는 기준 자료

### 광합성 / Photosynthesis
태양빛을 받아 주행 에너지로 흡수·전환하는 재능.
금색 빛의 중심 유입, 응축광, 연두빛 활성화가 기존 완료본의 특징입니다.
P5.2 Game 적용·사용자 승인 완료.

### 독주 / Solo Run
안정적이고 여유로운 선두 주행.
최종 ID는 talent.solo_run.static_ribbon입니다.
차량 주변과 차체 위에서 짧은 황금빛 구간이 뒤로 흐르는 고정 리본 F2 방식이며, Game 적용·사용자 승인 완료입니다.
과거 P3.2나 동적 메시 F 시안으로 되돌리지 마세요.

### 제로의 영역 / Zero Zone
극한 집중·정밀한 판단·초감각적인 주행.
청백색 집중광과 방향성 빛 요소를 사용하는 기존 완료본을 유지합니다.

새 영상이나 이번 실사풍 지침을 이유로 이 3종을 자동 재작업하지 마세요.

## 6. GPT 아트 리소스 요청

합의된 연출에 필요한 아트는 GPT에서 제작합니다.
Claude가 임의의 단순 도형이나 임시 이미지로 최종 품질을 대체하지 말고, 필요한 리소스를 구체적으로 요청해주세요. 기존 리소스로 충분하면 재사용합니다.

각 요청에 포함할 내용:
- 재능명과 제안 파일명
- 리소스의 역할과 첨부 영상에서 참고할 장면·타임스탬프
- 실사풍 재질·색·발광·가장자리 특성
- 최종 PNG 해상도·비율·투명 RGBA·여백
- 선두/꼬리 및 기준 방향
- sprite·particle·ribbon 등 적용 방식
- 단일 구간 매핑인지, 반복 가능한 타일 질감인지
- 좌우 별도 이미지 필요 여부
- 실제 경기에서 예상되는 표시 크기
- 포함하면 안 되는 요소

해상도와 리소스 수는 실제 표시 크기와 사용 방식에 맞춰 최소한으로 제안합니다.
파일을 전달받으면 실제 크기·alpha·방향을 확인하고 asset 등록과 export 연결을 진행하세요.

## 7. 작업량·성능·검증 기준

- 기존 Studio 기능과 공통 구현을 우선 활용합니다.
- Studio 지원이 Game 지원을 보장하지 않습니다. 필요한 type·anchor·modulation·LOD의 Game 지원은 전달 전에 구분해주세요.
- 공통 기능 확장이 필요하면 이유·대안·변경 범위를 먼저 설명합니다.
- 매 프레임 불필요한 메시·텍스처 생성은 피하고, 초기 준비 비용도 고려합니다.
- 동시 발동 조건은 해당 재능의 실제 규칙에 맞춰 정합니다. 독주의 검증 조건을 모든 재능에 그대로 적용하지 않습니다.
- 초기 시안부터 실제 경기 크기에서 확인합니다.
- 시각 보정 중에는 해당 focused 검사와 필요한 parse/diff만 수행합니다.
- 반복 전체 회귀·canonical export·SHA 전수 검사·대량 캡처·장문 보고는 하지 않습니다.
- 명령 실행이 불가능한 연결에서는 실행·테스트 완료를 주장하지 말고, 미확인 항목과 사용자 실행 방법을 안내합니다.
- Game 전달 시 package를 생성하고 ID·경로·필요한 지원·검증 결과만 짧게 인계합니다.
- 완료 후 불필요한 중간 산출물은 정리합니다.
- 포스필드 타이어 보조 VFX는 중단·제거된 작업이므로 재개하지 않습니다.

사용자가 첫 재능과 발동 애니메이션을 제공하면, 영상의 연출을 해석하고 경기용 VFX의 추천 방향부터 제안해주세요.
## 8. 사용자 보충 지시 (2026-09-29)

- Game 프로젝트 `C:\GodotProjects\DesktopIdleRacing`은 읽기 전용 참조. Game 파일·설정·package는 직접 변경하지 않는다(Game 수정은 Codex).
- 작업 전 공용 작업 안내 `DesktopIdleRacing/docs/VFX_EXPORT_PACKAGE_V1.md#shared-vfx-workflow`와 해당 재능의 최신 코드·계약을 먼저 읽는다.
- 구현 전 필요한 기능이 기존 renderer·helper·preset에 있는지 해당 범위만 확인하고 재사용한다. 찾지 못했다는 이유만으로 새 renderer나 비슷한 helper를 만들지 않는다. 실제 미지원이 확인되면 필요한 확장과 대안을 짧게 제안한다.
- Game 확장이 필요한 시안은 아트·구현을 크게 진행하기 전에 Codex가 수용 범위를 확인할 수 있게 요청사항을 작성한다.
- 계약 변경 없이 기존 기능으로 가능한 작업은 Codex의 별도 승인을 기다리지 않고 합의된 범위에서 진행한다.
- 다른 도구가 작성한 코드의 스타일만 바꾸거나 관련 없는 구조를 정리하지 않는다.
- 직접 실행하지 못한 테스트·Godot 실행·export는 미실행으로 표시한다.
- 완료 시 공용 인계 형식으로 변경점과 미확인 항목만 전달한다.
- 실사풍은 결과물의 기준이다. PNG 사용을 의무화하거나 절차적 표현을 보조로만 제한하지 않는다. 기존 기능으로 자연스럽고 가벼운 결과가 가능하면 활용한다.
- Game 지원 여부는 CURVE_FLOW F2만이 아니라 실제 loader·factory·renderer·기존 package를 확인해 판단한다.

### 경기 환경 (사용자 제공)
- 탑뷰 방치형, Windows 바탕화면 위젯 모드, x1 게임 해상도 1136×639.
- 일반전·그랑프리 모두 한 번에 10대 출전.
- 기본 부스터, 고속 바람선, 특수장비(슈퍼부스터 등), 날씨(비·눈) 이펙트가 상시 발생하는 상태에서, 1초 이내 동시 2~3대 재능 발동 가능성이 높고, 다른 재능 지속 중 추가 발동까지 합치면 5~8대가 동시에 재능 VFX를 가질 수 있다. 저부하·고품질을 함께 목표로 한다.
