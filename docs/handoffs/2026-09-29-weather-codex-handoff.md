## 0. 먼저 읽을 것 — 이전 작업과 다른 점

- **Studio package 작업이 아니다.** Game의 `WeatherVisualController.gd`, 날씨 셰이더, `weather_defs.json`의 `visual_profiles`, `RaceManager.gd`의 날씨 준비·전환 부분을 Codex가 수정한다. Studio 계약·loader·factory·VFX package는 관여하지 않는다.
- 설계·수치·아트 검수는 Claude가 했다. 이전 날씨 효과는 Codex가 코드 생성 타일로 직접 만들었으므로, 이번 문서는 그 구현을 기준으로 하지 않는다. 기존 `visual_profiles` 키(`gloss_*`, `haze_pulse_*`, 반복 횟수형 `tile_scale_*`)는 새 의미로 대체해도 된다.
- Game 코드에 대한 서술은 Claude의 **읽기 전용 분석과 Codex 사전 확인 회신**이 근거다. 실제 판단은 코드·실행 기준으로 하고, 충돌 시 추측하지 말고 사용자에게 확인한다.
- 수치는 x1(1136×639) **화면 px 기준 초안**이다. 사용자 격리 화면 확인 후 조정할 것을 전제로 `weather_defs.json`에서 바꿀 수 있게 둔다.
- 날씨 전환 전체 지연(차량 컨텍스트, 타이어 VFX 재준비 등)은 Codex 별도 조사와 겹친다. 이 인계는 **트랙 날씨 표현 몫**만 다룬다.

## 2. 구조 (사전 확인 회신 반영)

### 2-1. 색보정 = 트랙 스프라이트에 직접

- `track_sprite`(AnimatedSprite2D)와 `foreground_overlay`에 **같은** grade ShaderMaterial 1개. 4fps 프레임 교체 시 material 재생성 금지.
- 기존 필터 덮개(`WeatherTrackFilter`)와 폭염 필터 셰이더는 제거하고 grade 셰이더 1개로 통합.
- **알파 보존 규칙**: `COLOR.a`는 항상 **왜곡 전 원본 UV의 알파**. 아지랑이 왜곡은 RGB에만 적용하고, 왜곡된 좌표의 샘플 알파가 낮으면 원본 RGB로 섞는다(`rgb = mix(orig.rgb, warped.rgb, warped.a)`) → 외곽 어두운 테두리·클릭 경계 어긋남 방지. 위젯 입력 알파 캐시는 원본 텍스처 기준 그대로.
- 연산 순서: 채도 → 틴트 혼합 → 밝기 배율 → 대비(0.5 기준) → 하이라이트 올림(luma smoothstep 0.6~1.0) → 안개 더하기. 맑음 = 항등값. 맑음이 확정된 뒤에는 material을 해제해도 된다(해제·재부착 시 재질 재생성이 아니라 같은 인스턴스 재사용).

### 2-2. 강수 = 월드 안, 절대 z로 차량 위·HUD 아래

> **정정 (2026-09-29, Codex 질의 반영)**: 월드와 HUD가 같은 기본 Canvas라서 강수 전용 CanvasLayer만 추가하면 HUD까지 덮는다는 Codex 지적이 맞다. 캔버스 구조를 나누는 대신, 기존 z 규칙을 이용하는 아래 방식을 **1순위**로 한다. `main.tscn`과 월드 경로는 바꾸지 않는다.

- 현재 z 규칙(읽기 전용 확인): `RaceWorld` z 0(상대) / foreground overlay 3000(TrackController 기준 상대) / 차량 `depth_sort_y × 4` / 차량 이름표·컷인 **4095(절대)** / `GameScaleRoot` 직계 HUD Control **4096(절대)** (`RaceManager._apply_ui_canvas_order`).
- 강수 Sprite2D를 **트랙 스프라이트의 형제(TrackController 아래)**에 두고 `z_as_relative = false`, `z_index = 4000`. 트랙과 같은 부모·같은 변환이므로 **좌표·배율 동기화가 필요 없다**(현재 `_sync_overlay_transform`과 같은 방식으로 충분). 마스크는 현재 트랙 프레임 알파.
- 결과 순서: 트랙·차량·foreground < **강수 4000** < 차량 이름표·컷인 4095 < HUD 4096.
- **Codex 확인 조건**: ① 경기 중 차량 depth z 최대값이 4000 미만인지(트랙 좌표 y × 4 기준 추정 ≈3800 이하), ② 4000~4094 사이에 강수 위에 있어야 할 월드 요소가 없는지, ③ `RaceAbilityScreenEffect`(z 90) 등 상대 z UI가 실제로 HUD 쪽 부모 아래에 있는지.
- **대안(조건 불충족 시에만)**: Codex 제안대로 월드 전용 CanvasLayer 분리(월드 → 강수 → HUD, `main.tscn`·`RaceManager.gd`의 월드 경로·변환 연결 변경, HUD 배치·게임 로직 유지). 사용자 승인 범위: 이 대안이 필요하면 착수 전 이유만 짧게 보고.
- 타일 크기는 **반복 횟수가 아니라 텍셀 크기**로 지정한다. 표의 "텍셀:화면 px"를 x1 트랙 표시 배율(≈0.54, 실제 값은 트랙 변환에서 계산)로 나눠 트랙 px당 텍셀 크기로 환산하고, **가로·세로 같은 값**(정사각 텍셀)을 쓴다. 속도도 같은 방식으로 트랙 px/s로 환산. 그러면 화면 배율 모드에서도 트랙과 함께 커진다.
- 한 셰이더에서 3층 + 마스크 = 텍스처 읽기 4회. 층별 uniform: 타일, 텍셀 크기, 속도 벡터, 불투명도, UV 오프셋, 회전(도), (눈) 흔들림 진폭·주기·위상. 전체 강도 uniform `intensity`(0~1)가 모든 층 불투명도에 곱해진다.
- 파티클·노드 다수·화면 복사(SCREEN_TEXTURE/BackBufferCopy) 금지.

### 2-3. 수명과 전환

- 날씨 컨트롤러·grade material·강수 노드는 **경기 SETUP에서 1회 생성, 경기 종료/정리 때 1회 해제**. 날씨 전환 때 생성·삭제 없음.
- **색보정 전환**: 새 날씨가 오면 *현재 표시 중인 값*에서 새 목표값으로 1.5초 선형(또는 smoothstep) 보간. 보간 도중 또 바뀌면 그 시점 표시값에서 최신 목표로 다시 1.5초.
- **강수 전환 규칙** (동시에 한 종류의 타일 세트만 활성):

| 현재 표시 | 새 날씨 | 동작 |
|---|---|---|
| 없음 | 비/눈 | 해당 타일 세트 바인딩 → `intensity` 0→1, 0.9초 |
| 비/눈 | 없음(맑음·폭염) | `intensity` 현재값→0, 0.6초 × 현재값. 0 도달 후 강수 노드 숨김(삭제 아님) |
| 비 | 눈 (또는 반대) | 현재값→0(0.6초 × 현재값) → 0에서 타일 세트 교체 → 0→1, 0.9초 |
| 페이드아웃 중 | 또 다른 변경 | 페이드아웃 계속, 0 도달 시 **가장 최근** 목표로 교체·페이드인(중간 목표 건너뜀) |
| 페이드아웃 중 | 현재 표시 중인 것과 같은 종류 | 타일 교체 없이 현재값에서 1까지 페이드인(0.9초 × (1−현재값)) |
| 페이드인 중 | 다른 종류 | 현재값에서 페이드아웃 규칙 적용 |

- 전환 시간은 경기 시간(일시정지·배속 규칙은 기존 날씨 timeline과 같은 delta) 기준.

### 2-4. 렌더 준비 완료 조건 (SETUP)

- 날씨 준비를 Static Ribbon 준비와 **별도 작업**으로 두고 SETUP 완료 대기 흐름에 합류(완료·취소·실패 정리 동일 원칙).
- 준비 대상: grade 셰이더 1개, precipitation 셰이더 1개(비 세트·눈 세트 각각 바인딩 상태), 타일 4장 + 노이즈 로드.
- **완료 조건**: 각 셰이더가 **운영과 같은 캔버스 경로(같은 blend·render_mode·기본 Canvas)**로 실제 가시 픽셀을 그린 프레임이 `RenderingServer.frame_post_draw` 이후 확인될 것. `intensity`/알파 0, `visible=false`, 화면 밖 배치만으로는 완료로 보지 않는다(회신 4 반영). 방법(오프스크린 SubViewport 등)은 Codex 결정이되, 사용자에게 보이는 깜빡임이 없어야 하고 임시 노드·뷰포트는 정리한다.
- 준비 실패 시: 날씨 표현 없이 경기 진행 + 경고 1회(레이스 차단 여부는 기존 정책과 맞춰 Codex 판단).

## 5. 확인 요청 (최초 운영 사용·Studio 미검증 항목)

- **처음 쓰는 구조**: 트랙 스프라이트·foreground에 material 직접 적용, 강수의 절대 z 4000 배치, 날씨 SETUP 준비. 모두 Game에 선례가 없다.
- **기존 효과와의 중첩**: 강수가 차량·헤드라이트·재능 VFX(나이트 비전 등)·foreground 위에 온다. 가까운 층이 차량 판독을 가리지 않는지, 야간 트랙에서 빗줄기가 튀지 않는지.
- 트랙 프레임 교체(4fps) 때 강수 마스크·grade 텍스처가 한 프레임 어긋나지 않는지.
- 창 크기·화면 배율 모드 변경 시 강수가 트랙과 계속 정렬되는지(같은 부모라 기대상 자동).
- 위젯 입력(클릭 영역) 알파가 그대로인지.
- Studio에서 검증한 것은 **PNG 정적 검수와 정지 화면 합성 모의뿐**이다. 움직임·전환·실제 Godot 합성은 미검증.

## 6. 검증

**Codex 실행 요청**
- 개선 전 기준: `WeatherTransitionProbe.gd`(최초/반복 전환), `NightVisionGameProbe.gd`식 평상시 frame·draw call·viewport GPU. 트랙 표현 / 차량 컨텍스트 / 타이어 VFX를 구분 기록.
- 개선 후 같은 fixture 재측정 + focused 검사(전환 규칙 표의 각 행, 준비 완료·취소·실패 정리, 경기 정리 후 잔존 노드 없음, 알파 보존).
- 사용자 확인용 격리 진입점: 트랙·날씨 고정 및 전환 순서 지정(예: 맑음→비→눈→폭염→맑음, 각 6초), 낮 트랙(beach, alps, desert)·밤 트랙(newyork 또는 seoul), 20대 주행. 실행 명령을 인계에 적어 달라.

**Claude가 한 것 / 안 한 것**
- 한 것: 타일 4장 수치 분석(크기·알파·투명부 색·이음매·개수·길이·기울기), 2×2 반복 확인, beach·alps 트랙 0.54배 정지 합성 모의.
- 안 한 것: Godot 실행, 셰이더 작성, 움직임·전환 확인, 성능 측정.
