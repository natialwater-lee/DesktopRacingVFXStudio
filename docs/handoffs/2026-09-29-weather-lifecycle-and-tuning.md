# 트랙 날씨 — 경기 전후 유지 + 1차 수치 보정 (Studio → Codex)

2026-09-29 · 작성: Claude (설계·검수) · 대상: Game Codex · 선행: `DesktopIdleRacing/docs/WEATHER_TRACK_GAME_HANDOFF.md`

## 0. 요약

- 사용자 녹화 4개(NY 야간 비 주행, NY 카운트다운→출발(야간·눈), 해변 카운트다운→출발(폭염), 해변 비 결승→결과 팝업)를 검토했다. 날씨 표현 자체는 의도대로 동작한다. **수치는 폭염만 약하다.**
- **주 요청은 수명(lifecycle)**: 지금은 카운트다운 동안 맑음으로 보이다가 출발 후 페이드인되고, 결승 직후 결과 팝업 뒤로 곧바로 맑음이 된다. **UI 상태 때문에 날씨가 기본값으로 돌아가면 안 된다**(사용자 요구).
- 원인(읽기 전용 확인): ① `configure()`는 중립에서 시작하고 `advance_weather()`로만 페이드인하는데, 이 함수는 `_advance_dynamic_weather`에서 `RaceState.RACING`일 때만 호출된다 → SETUP·COUNTDOWN 동안 중립. ② `_finish_race()`가 `_clear_dynamic_weather()` 직후 `_clear_weather_visuals()`로 컨트롤러를 해제한다.
- 게임 판정·timeline·주행 효과·타이어 VFX 정리 시점은 바꾸지 않는다. **표시만** 바꾼다.

## 1. 수명 규칙 (필수)

| 상태 | 표시 | 날씨 종류 변경 | 애니메이션(빗줄기 낙하·눈 흔들림·아지랑이) |
|---|---|---|---|
| SETUP (렌더 준비 완료 후) | **시작 날씨(`config.weather_id`, timeline t=0)를 즉시 100%** — 색보정 목표값, 강수 intensity 1. 페이드 없음 | 없음 | 진행 |
| COUNTDOWN | 시작 날씨 유지 | 없음 | 진행 |
| RACING | 현재 구현 그대로(timeline 기준 전환, 1.5s/0.6s/0.9s 규칙) | timeline | 진행 |
| FINISHED → 결과 팝업 → 다음 경기 대기 | **결승 순간 표시 상태를 그대로 유지**. 진행 중이던 전환은 그 목표까지 마저 끝낸다 | 없음(종류 고정) | 진행 |
| 경기 중·후 각종 팝업/관리/피트/설정 UI | 유지 | 규칙대로 | 진행(트리 일시정지 중에는 멈춰도 됨) |
| 다음 경기 — **같은 트랙이 화면에 남아 있는 경우** | 표시 중 날씨 → 새 시작 날씨로 SETUP~COUNTDOWN 동안 **1.5s 전환**(기존 전환 규칙 재사용) | 1회 | 진행 |
| 다음 경기 — 트랙이 바뀌는 경우 | 새 트랙 SETUP에서 새 시작 날씨 즉시 100% | — | 진행 |
| 표시 해제 | 트랙 노드 제거·교체, 트랙이 없는 화면(시작 화면 등)으로 이동, 날씨 없는 모드(`is_difficulty_play()` 아님), 렌더 준비 실패 | — | — |

- **결과 화면에서 timeline을 계속 흘리지 않는 쪽을 권장**한다. 결과 팝업은 약 10초이고, 그 사이 날씨가 바뀌면 경기 결과와 무관한 변화가 눈에 띄며, timeline·HUD 예보를 경기 후까지 살려야 한다. 사용자도 "흐른 시간 기준 변화도 좋다"는 선택 사항으로만 언급했다. 필요하면 후속으로 검토.
- **시각 시계 분리**: 날씨 종류 변경·timeline은 기존처럼 경기 물리 delta(RACING)에만 묶고, 애니메이션 시간과 SETUP/COUNTDOWN/FINISHED 이후의 전환 진행은 별도 시각 delta(프레임 delta)로 진행한다. 시각 delta가 게임 판정·`_race_elapsed_sec`에 들어가면 안 된다.
- `configure()`에 즉시 적용 옵션(예: `immediate := true` → `_grade = _grade_target`, 해당 강수 바인딩 후 `_intensity = 1`)을 두고 SETUP에서 사용. 같은 트랙 재사용 여부로 즉시/전환을 고른다.
- `_finish_race()`의 `_clear_weather_visuals()`는 제거하거나 "종류 고정" 호출로 바꾸고, 실제 해제는 `_clear_current_race()`·트랙 교체·화면 이탈 경로에서만. `_clear_current_race(keep_track := true)`로 트랙을 유지하는 경로에서는 해제 대신 다음 경기 전환 규칙을 따른다.
- HUD 날씨 패널(`_hide_weather_ui`)은 이번 범위에서 **바꾸지 않는다**(결승 후 예보 문구가 의미 없어지므로 숨김 유지). 사용자가 원하면 별도로.

### 1-1. 확인 요청

- 카운트다운 첫 프레임부터 시작 날씨가 100%인지(페이드 없이), 출발 순간 튐 없음.
- 결승 → 결과 팝업 → "다음 경기" 자동/수동 진행까지 날씨 유지, 결과 화면에서 빗줄기·눈이 계속 움직임.
- 결승 순간 전환 도중이면 그 목표까지 완료 후 고정.
- 같은 트랙 연속 경기에서 이전 날씨 → 새 시작 날씨 1.5s 전환, 다른 트랙에서는 즉시.
- 경기 중 관리·설정·피트 UI를 열고 닫아도 유지.
- 시작 화면 복귀·트랙 교체·레이스 취소(SETUP 중 취소 포함)·준비 실패 시 잔존 노드·material 없음, 원래 트랙 material 복원.
- 날씨 판정·timeline·타이어 VFX·저장 데이터 불변.

## 2. 1차 수치 보정 (`weather_defs.json` `visual_profiles`만)

녹화 검토(정지 프레임 + 확대, 움직임은 사용자 녹화 재생 기준):

| 날씨 | 평가 | 보정 |
|---|---|---|
| 비 | 야간(NY)은 빗줄기·어두운 색보정이 잘 읽힘. 주간(해변)은 빗줄기가 옅어 맑음과 차이가 작음 | 주간만: `brightness` 0.91→**0.88**, 먼 층 `opacities` 0.60→**0.68**, 가까운 층 0.55→**0.65**. 야간 값 유지 |
| 눈 | 야간 NY에서 큰 눈송이 보케·채도 감소가 자연스러움. 차량·트랙 가림 없음 | **유지** |
| 폭염 | 출발 전/후 비교 시 모래·물이 조금 따뜻해지는 정도라 맑음과 구별이 약함. 아지랑이 0.5px는 x1에서 거의 인지 안 됨 | `tint_mix` 0.10→**0.14**, `saturation` 0.10→**0.14**, `contrast` 0.06→**0.08**, `highlight` 0.04→**0.06**, `heat_amplitude` [0.5,0.3]→**[0.8,0.5]**. 야간 `tint_mix` 0.05→**0.07** |

- 아지랑이는 트랙 아트의 글자·라인이 출렁여 보이면 [0.65,0.4]로 되돌린다(Codex가 격리 화면에서 확인한 뒤 판단 가능).
- 코드 변경 없음. 나머지 키 유지.

## 3. 검증·보고

- focused: 1-1 각 항목. 기존 `WeatherVisualTransitionTest`, `DynamicWeatherRuntimeTest` 유지 통과.
- 성능 재측정은 불필요(수명 변경은 생성 횟수를 줄이는 방향). 결과 화면에서 날씨 애니메이션이 계속 도는 비용만 짧게 기록.
- 보고: 공통 인계 형식. 사용자 확인용 녹화 방법(카운트다운 시작~결과 팝업 포함)을 적어 달라.
