## 1. 폭염 아지랑이 (데이터)

사용자: x1 화면에서 일렁임이 잘 느껴지지 않는다 → 더 굵게.

| `visual_profiles.heatwave.grade` | 현재 | 요청 |
|---|---|---|
| `heat_amplitude` (화면 px, 가로/세로) | [0.8, 0.5] | **[2.0, 1.4]** |
| `heat_wavelength` (화면 px) | 50 | **100** |
| `heat_speed` (px/s, 위로) | 12 | **20** |

- 색보정 값(틴트·채도·대비·하이라이트)은 유지. 야간 값도 유지.
- 유지할 계약: 알파는 원본 UV 기준(위젯 입력 경계 불변), 왜곡은 RGB만, 차량·타이어 자국·wake는 왜곡하지 않음.
- 확인: 파장을 키웠을 때 128×128 노이즈의 반복 무늬가 보이지 않는지, 연석·피트 번호 등 글자와 트랙 외곽(알파 경계)이 거슬리게 출렁이지 않는지, 차량이 도로 위에서 떠 보이지 않는지. 과하면 [1.6, 1.1]까지 낮춰도 된다(판단 근거를 보고에 적어 달라).
- 부하 변화 없음(같은 샘플 수).

## 2. 날씨 전환 속도 (상수 → 데이터, 값 변경)

사용자: 부드러운 전환은 좋으나 조금 더 천천히 바뀌어 현실감을 주고 싶다(과하지 않게).

| 항목 | 현재 | 요청 |
|---|---|---|
| 색보정 보간 | 1.5s | **3.0s** |
| 강수 페이드 인 | 0.9s × 남은 강도 | **2.5s** × 남은 강도 |
| 강수 페이드 아웃 | 0.6s × 현재 강도 | **2.0s** × 현재 강도 |

- 현재 컨트롤러 상수인 세 값을 `weather_defs.json`(예: `visual_transition` 키)로 옮겨 조정 가능하게.
- 전환 규칙(최신 목표 우선, 표시값에서 이어서 보간, 비↔눈은 0까지 내린 뒤 타일 교체)은 그대로. 비↔눈 전체 약 4.5s.
- **경기 시작(SETUP·COUNTDOWN)의 즉시 100% 적용과 결승 후 유지 규칙은 그대로.** 같은 트랙 다음 경기로 넘어갈 때의 전환도 새 시간 사용.
- 게임 효과(안정성 압력 등)는 지금처럼 즉시 적용 — 시각만 늦게 따라온다.

### 2-1. wake·타이어 자국과의 어긋남

- 비·눈 wake는 날씨 ID 변경 즉시 최대 알파로 발생한다. 전환이 길어지면 "비는 아직 옅은데 물보라는 최대"가 된다.
- 요청: wake 조각 생성 시 알파에 **현재 트랙 강수 강도(`intensity` 0~1)**를 곱한다(생성 시점 값, 조각별 고정). 강수가 사라지는 중에는 새 wake도 같이 옅어지고, 강도 0이면 발생 생략.
- 타이어 자국의 날씨별 색 전환은 지금처럼 즉시(생성 시점 날씨) 유지.
- 비·눈 타이어 package(바퀴 파티클)는 지금처럼 즉시 시작·종료(작아서 수용). 어색하면 알려 달라.
