## 0. 사용자 증상

경기 시작 후 약 2.7초, 4.3~7초 무렵 프레임이 튀는 느낌(이전부터). 피트스톱 에이스 부하 측정에서 같은 시점의 70~95ms 프레임이 재현됐고, **VFX를 즉시 지운 비교 실행에서도 똑같이 발생** → VFX 원인 아님. 사용자: "신규 차량이 출발할 때 발생하는 현상 같다."

## 1. 측정 방법

Codex `tests/vfx/manual/PitStopAceGameProbe.gd`의 `PitManager` 고정 경기(20대, 6대 실제 피트 정비 → 교체) 위에 Claude 스크립트(외부 파일)로:
- 프레임별 차 피트 상태·차체 텍스처 변경·부스터/특수장비 작동과 30ms 초과 프레임 대조, 노드·오브젝트·텍스처 메모리 변화.
- 차량 스크립트를 측정용 하위 클래스로 바꿔 `CarAgent._apply_active_loadout`(3924행) 단계별 시간 측정.
- debug GL, 고사양 PC(Ryzen 7 9800X3D/RTX 5070 Ti). 저사양에서는 수 배.

## 3. 원인

1. **차량 그림자 생성**: 교체 시 `_apply_visual_settings()`(6004행) → `CarShadow.configure_sprite_shadow` → `get_soft_alpha_shadow_texture`(`CarShadow.gd` 88행)가 **처음 보는 차체 텍스처마다** 메인 스레드에서 `get_image()` → (압축 해제) → `_build_soft_alpha_shadow_image`(번짐 처리) → `ImageTexture.create_from_image` 를 수행. 텍스처당 약 30ms. 캐시(static)는 있으나 **다음 로드아웃 차량은 교체 순간에 처음** 만들어진다. 피트 교체가 몰리면(같은 랩에 여러 대) 한 프레임에 겹친다.
2. **특수장비 첫 작동**: 교체된 로드아웃의 특수장비가 처음 켜질 때 관련 텍스처·리소스를 지연 로드(텍스처 메모리 +1.4~1.5MB, 66~71ms).
3. 경기 시작(36ms)도 1과 같은 그림자 생성이 시작 차량 수만큼 일어나는 것으로 추정(미분리).

## 4. 개선안 (Codex 수정 요청, 우선순위 순 — 규칙·외형 변경 없음)

1. **그림자 미리 만들기**: 경기 준비(SETUP/COUNTDOWN) 단계에서 **모든 참가자의 모든 로드아웃 차량 텍스처**(현재 + 다음)에 대해 `get_soft_alpha_shadow_texture`를 미리 호출해 static 캐시를 채운다. 한 프레임에 몰지 말고 프레임당 1~2개씩 분산(또는 이미지 처리 `_build_soft_alpha_shadow_image`는 WorkerThreadPool에서, `ImageTexture.create_from_image`만 메인 스레드). 차량 텍스처도 `ResourceLoader.load_threaded_request`로 미리 로드. 같은 텍스처·프로필은 이미 캐시되므로 경기 사이에는 추가 비용 없음.
   - 방치형 원칙: 준비 단계에서도 관리 버튼·메뉴 조작이 막히거나 늦어지면 안 된다(분산 처리로 프레임당 수 ms 이내).
2. **특수장비 리소스 미리 준비**: 참가자 로드아웃 중 특수장비가 있는 것의 시각 리소스(텍스처·package·풀)를 경기 준비 단계에서 미리 로드/워밍업. 첫 작동 시 지연 로드 제거.
3. (확인) 경기 시작 36ms가 1로 해소되는지.

예상: 교체 프레임 52~93ms → 약 10ms 이하(교체 처리 1ms × 대수), 특수장비 첫 작동 66~71ms → 일반 프레임 수준.
