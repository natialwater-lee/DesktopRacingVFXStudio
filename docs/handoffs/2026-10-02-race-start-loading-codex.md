# 게임 시작 → 첫 경기 시작 로딩 — Claude 측정 → Codex 개선 요청

2026-10-02 · 분석: Claude (Game 소스 수정 없음, 외부 측정 스크립트만 실행) · 대상: Game Codex
관련: `docs/handoffs/2026-10-02-pit-swap-frame-spike-codex.md`(SETUP 그림자 준비가 추가된 작업)

## 0. 사용자 증상

게임을 새로 켜고 경기를 시작할 때 약 2초 동안 트랙과 관리 버튼만 보이고 레이서 패널·차량·하단 UI가 비어 있다가 한꺼번에 나타남(사용자 녹화 0~2.2s). 사용자: 줄일 수 있으면 줄이자(Claude 권장안 승인).

## 1. 측정 (scratchpad `startup_probe.gd`, 일반 `main.tscn`, 사용자 세이브 복사본·격리 APPDATA, debug GL, 고사양 PC, 2회)

| 구간 | 시간 |
|---|---:|
| `main.tscn` load | 2.62~2.65s |
| `add_child`(_ready) | 1.15~1.20s |
| SETUP 진입(launch 기준) | 4.00~4.08s, 그 프레임 **218~220ms** |
| StaticRibbonPreparation | 1프레임(52~66ms) |
| WeatherVisualPreparation | 3프레임 |
| **RaceVisualPreparation** | **2.51~2.53s, 361~363프레임, 프레임 최대 15ms**(준비 자원 111개) |
| COUNTDOWN 진입 프레임 | **152~164ms** |

- 사용자가 본 빈 화면 약 2초 = **RaceVisualPreparation 2.5초**(이번 그림자 미리 만들기 + 렌더 워밍업). CPU가 바쁜 게 아니라(프레임 ≈7ms) **자원 하나마다 렌더 제출을 기다리며 몇 프레임씩 직렬로 진행**해서 길다(111개 × 약 3프레임).
- launch 직후 3.8초(씬 로드 + _ready)는 엔진·리소스 첫 로드로 별도.

## 2. 개선안 (Codex 수정 요청 — 경기 중 버벅임 해소 효과는 유지, 외형·규칙 변경 없음)

1. **UI·차량 먼저 표시**: SETUP 진입 시 레이서 패널·하단 UI·차량(현재 로드아웃)을 바로 보이게 하고 준비는 뒤에서 진행(사용자 체감상 "로딩 화면" 제거). 관리 버튼·메뉴 조작성 유지(방치형 원칙).
2. **렌더 워밍업 묶음 처리**: 한 번의 렌더 제출에 여러 자원(예: 10~20개)을 같은 SubViewport에 함께 그려 확인 → 111개 기준 약 2.5s → 0.3s 수준 예상. 텍스처 로드는 `ResourceLoader.load_threaded_request`로 병렬, 그림자 이미지 처리는 WorkerThreadPool(이미 분산 중이면 유지).
3. **우선순위 분리**: 카운트다운 전에는 **현재 로드아웃(출발 차량)** 자원만 필수로 준비하고, **다음 로드아웃·특수장비** 자원은 카운트다운·경기 초반에 백그라운드로 계속 준비(피트 교체·특수장비 첫 작동 전에만 끝나면 됨). 준비가 덜 끝난 자원이 필요해지면 그 자원만 즉시 준비(현재 동작 유지).
4. **COUNTDOWN 진입 프레임 150~160ms, SETUP 진입 프레임 220ms** 원인 확인·분산(UI 일괄 생성/레이아웃 추정, 미분리).

예상: 빈 화면 약 2.5s → 거의 없음(UI 즉시 표시), 카운트다운 시작까지 대기 ≈ 0.3~0.5s.
