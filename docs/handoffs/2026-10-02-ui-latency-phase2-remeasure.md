## 3. 3단계 (사용자 승인 2026-10-02 — 1·2·3 모두 진행, 3은 아래 "점진 표시" 방식)

1. 레이서 선택기 모델을 UI 스냅샷 세대 + 선택 로드아웃 기준으로 캐시 → 슬롯 선택·장착 약 −35ms.
2. 부품 보관함 팝업도 차고와 같은 카드 재사용·폰트 1회 적용 → 약 94 → 30ms대 예상.
3. 차고 첫 열기: 64장 = **선택 차량 1대의 360° 회전 미리보기 프레임**(`GaragePreviewFrames.frames_for`, 640×480 RGBA, import 무손실 `compress/mode=0`). 디스크는 작지만(.ctex 약 68KB/장) 메모리에는 장당 약 1.2MB → **차량 1대 약 78MB**, 40대면 약 3GB. 따라서 **게임 시작 시 전체 미리 로드는 하지 않는다**(사용자 우려 확인, 2026-10-02). 대신:
   - (권장) **점진 표시**: 첫 열기 때 기본 프레임 1장만 동기 로드해 바로 표시하고, 나머지 63장은 `ResourceLoader.load_threaded_request`로 백그라운드 로드 후 회전 시작. 메모리·게임 시작 시간 증가 없음.
   - (선택) 현재 선택된 차량 1대만 경기 중 유휴 시간에 백그라운드 미리 로드.
   - 프레임 수·해상도 축소는 외형 변경이라 사용자 결정 사항(현재 제안 안 함).
   - 첫 열기 307ms 중 이미지 로드 비중은 미측정(갱신 자체 약 86ms 포함) — 적용 시 Claude가 분리 측정.

고사양 PC 기준 현재 값은 대부분 체감 경계(약 50~100ms) 근처다. 저사양 PC에서는 2~3배가 될 수 있어 1·2는 효과 대비 비용이 낮은 편이다.

## 4. Codex 요청 작업 (3단계)

1. **레이서 선택기 모델 캐시**: `_get_garage_racer_selector_models()` 결과를 UI 스냅샷 세대(`get_profile_read_revision()`) + 경기/라인업 상태 기준으로 재사용. 슬롯 선택·부품 선택·장착/해제처럼 레이서·로드아웃·차량이 바뀌지 않는 갱신에서는 다시 계산하지 않는다. 장착/해제로 바뀌는 표시(장착 부품 등)가 선택기 카드에 있다면 그 부분만 갱신.
2. **부품 보관함 팝업 카드 재사용**: `_refresh_parts_inventory_popup()`에 2단계 차고와 같은 방식(instance_id 기준 카드 재사용, 변경·삭제 카드만 갱신, `_apply_ui_fonts` 새 노드에만/1회) 적용. 필터·정렬 변경, 판매·잠금·합성·상자 개봉 후 갱신이 그대로 맞아야 한다.
3. **차고 첫 열기 점진 표시**: `GaragePreviewFrames.frames_for()` 경로에서 기본 프레임(`default_frame_for`) 1장만 동기 로드해 즉시 표시하고, 나머지는 `ResourceLoader.load_threaded_request`로 백그라운드 로드 후 완료 시 회전 시작. 로드 중 차량을 바꾸면 이전 요청 결과는 버리고(잘못된 차량 프레임 표시 금지), 팝업을 닫아도 오류가 없어야 한다. **게임 시작 시 전체 미리 로드는 하지 않는다**(차량당 약 78MB). 회전 속도·프레임 순서·기본 방향·접지(grounding) 보정은 기존과 동일. 64/32/16 프레임 세트 모두 지원 유지.
4. 1단계·2단계 개선(스냅샷, 카드 재사용, 상자·연구 캐시)은 유지.
