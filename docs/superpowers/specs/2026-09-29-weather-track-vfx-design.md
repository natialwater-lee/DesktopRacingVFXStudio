# 트랙 날씨 효과 (비·눈·폭염) — 개선 설계

> **최종 상태 (2026-09-30): 사용자 최종 승인.** Game 적용(절대 z 4000 강수, 트랙 직접 색보정, 부드러운 전환, SETUP 렌더 준비) + 경기 전후 날씨 유지·1차 수치 보정(`docs/handoffs/2026-09-29-weather-lifecycle-and-tuning.md`)까지 반영. 전달용 `exports/weather_track_v1/`은 Game 사본 확인 후 삭제.

2026-09-29 · 설계·리소스 검수: Claude · 아트: GPT · 구현: Game Codex · 승인: 사용자

## 0. 범위와 역할

- 대상: 트랙 전체에 덮이는 날씨 표현 `WeatherVisualController.gd` + `shaders/weather_*.gdshader` + `data/weather/weather_defs.json`의 `visual_profiles` (모두 Game).
- 제외: 날씨 판정·일정·주행 효과(`weather_effects`, timeline), 차량 타이어 물보라/눈가루 package(`driving.rain_tire_spray`, `driving.snow_tire_spray`), 맑음 상태.
- **Studio package로 만들지 않는다.** Game runtime은 `VEHICLE_LOCAL`만 렌더(`VfxRendererFactory.preflight_layer` → `unsupported_space_mode`), 시작 API도 `start_vehicle_effect`뿐이다. 트랙 전체 효과를 Studio 계약으로 옮기는 비용이 3종 대비 크므로 Game 셰이더 방식을 유지·개선한다(사용자 결정 2026-09-29).
- 역할: Claude는 이 설계·수치 초안·GPT 아트 요청·PNG 검수·Codex 인계. Codex는 구현·측정·격리 확인 진입점. Studio 코드는 변경하지 않는다.

## 1. 현재 상태 (Game 읽기 전용 확인)

| 항목 | 현재 | 문제 |
|---|---|---|
| 구성 | 트랙 스프라이트 위에 트랙 크기 Sprite2D 2장: 필터(z 0) + 강수(z 2). 폭염은 필터만 | 비·눈은 트랙 전체를 3번(트랙+필터+강수) 그림. 필터는 색을 섞은 반투명 면이라 실제 색보정이 아님 |
| 강수 무늬 | 코드로 128px 타일 생성(비: 1px 사선 44개, 눈: 1~2px 점 64개), `filter_linear` | 게임 크기에서 1.4~2.8배 확대되어 흐림. 실효 알파 ≈0.2 → 거의 안 보임 |
| 타일 배율 | 비 5×4, 눈 2.5×2 (UV 반복 횟수) | 트랙 1672×941에 가로·세로 횟수를 따로 줘서 **텍셀이 비정사각**(비 ≈1.42:1)으로 늘어남 |
| 깊이 | 같은 타일을 배율 1.73으로 한 번 더 | 두 층이 같은 무늬 → 반복 격자가 보이고 원근감 없음 |
| 눈 흔들림 | `sin(t + UV.y)` | 같은 높이 눈송이가 한 줄로 같이 흔들림 |
| 젖은 노면 | 푸른 틴트 7% + `sin(UV.x)` 가로 밝기 파동 | 실제 젖은 노면처럼 보이지 않음 |
| 폭염 | 따뜻한 색 12% 혼합 + 밝기 1.6% | 맑음과 거의 구별 안 됨 |
| 층 순서 | 강수 z 2 (TrackController 기준 상대) | 차량은 depth sort z(최대 ±4096)라 강수가 대부분 차량 **아래**에 그려질 가능성 |
| 전환 | 날씨 변경 시 컨트롤러·노드·재질 삭제 후 재생성, 즉시 교체 | 전환 순간 뚝 바뀜. 경기 준비 단계에서 셰이더 사전 준비 없음(무늬 텍스처만 준비) → 첫 전환 시 셰이더 준비 비용 가능성 |

평상시 부하는 작다(Codex 측정 viewport GPU ≈0.1ms, 야간·비). 개선 목표는 **같거나 적은 GPU 비용으로 화질 향상 + 전환 순간 비용 제거**.

## 2. 설계 원칙

1. 실사풍: 코드로 찍은 점·선이 아니라 촬영된 비·눈·열기처럼. 영화적 과장 없이 "날씨가 바뀌었다"가 한눈에 읽히는 강도.
2. 가독성: 차량(실제 20~24×41~49px)·트랙 라인·HUD를 가리지 않는다. 가까운 층일수록 수가 적고 얇게.
3. 낮/밤 공통: 야간 트랙(santa, seoul, newyork)에서도 과하게 밝지 않도록 야간 배율을 둔다.
4. 저부하 예산 (4장) 안에서만 설계.
5. 전환은 부드럽게, 전환 중 노드·재질·셰이더를 새로 만들지 않는다.

## 3. 날씨별 연출

수치는 **x1(1136×639) 화면 px 기준 초안**이다. 트랙은 1672×941 텍스처가 약 0.54배로 그려지므로 Codex가 트랙 px/UV로 환산한다. 최종값은 Game 격리 화면에서 사용자 확인 후 확정한다.

### 3-1. 비 (rain)

- **색보정(트랙 자체)**: 전체 8~10% 어둡게, 채도 -15%, 차가운 틴트(0.80, 0.88, 1.0) 10% 혼합, 대비 -5%. 흐린 날 빛. 가로 밝기 파동(gloss)은 제거.
- **빗줄기 3층** (위→아래로 약 15° 왼쪽으로 기울어 떨어짐, 모든 층 같은 방향 ±4°):

| 층 | 타일 | 텍셀:화면 px | 속도(px/s) | 불투명도 | 비고 |
|---|---|---:|---:|---:|---|
| 먼 층 | `weather_rain_far` | 1.0 | 260 | 0.35 | 촘촘·가늘게 |
| 중간 층 | `weather_rain_far` | 1.35 | 360 | 0.28 | UV 오프셋·+4° 회전으로 먼 층과 다른 배치 |
| 가까운 층 | `weather_rain_near` | 1.6 | 560 | 0.45 | 적고 길고 부드러운 모션 블러 |

- 생략: 노면 물튀김·물결(아스팔트 마스크가 없어 모래·물에도 생김 → 트랙별 마스크가 생기면 후속 검토), 번개·화면 섬광.
- 야간: 색보정 어둡게 절반(4~5%), 빗줄기 불투명도 ×0.8(밝은 줄이 튀지 않게).

### 3-2. 눈 (snow)

- **색보정**: 밝기 +3%, 채도 -20%, 차가운 흰 틴트(0.92, 0.96, 1.0) 8%, 옅은 안개감(흰색 4% 더하기).
- **눈송이 3층** (천천히 낙하 + 좌우 흔들림):

| 층 | 타일 | 텍셀:화면 px | 낙하(px/s) | 흔들림 진폭(px) | 불투명도 |
|---|---|---:|---:|---:|---:|
| 먼 층 | `weather_snow_far` | 1.0 | 28 | 4 | 0.55 |
| 중간 층 | `weather_snow_far` | 1.4 | 40 | 7 | 0.45 |
| 가까운 층 | `weather_snow_near` | 1.8 | 60 | 12 | 0.60 |

- 흔들림 위상은 층마다, 그리고 **가로 위치(x)마다** 다르게(한 줄로 같이 흔들리지 않게). 주기 3~6초.
- 생략: 눈 쌓임 표현(트랙 아트가 이미 설원/비설원으로 구분되어 있음).
- 야간: 불투명도 ×0.85.

### 3-3. 폭염 (heatwave)

- **색보정**: 따뜻한 틴트(1.0, 0.78, 0.50) 10%, 채도 +10%, 대비 +6%, 밝은 부분 살짝 올림(하이라이트 +4%).
- **아지랑이**: 트랙 이미지를 읽는 좌표를 작은 노이즈로 흔든다. 진폭 가로 0.5 / 세로 0.3 화면 px, 파장 40~60 화면 px, 노이즈가 위로 천천히 흐름(약 12 px/s). 화면 복사(SCREEN_TEXTURE/BackBufferCopy)는 쓰지 않는다.
- 선택(사용자 확인 후): 아주 느린 밝기 호흡(0.1Hz, ±1%).
- 생략: 태양 광원·렌즈 플레어·화면 전체 섬광.
- 야간(seoul·newyork·paris 등에서 드물게 발생): 색보정 따뜻함 절반, 하이라이트 올림 없음, 아지랑이 유지.

## 4. 구조와 부하 예산 (Codex 구현 제안)

| 항목 | 제안 | 현재 대비 |
|---|---|---|
| 색보정 | **트랙 스프라이트(와 foreground overlay)에 색보정 ShaderMaterial을 직접 적용**. 비·눈·폭염·맑음을 하나의 grade 셰이더로(틴트·어둡게·채도·대비·하이라이트·아지랑이 진폭). 맑음 = 항등값 또는 material 해제 | 필터 덮개 1장 제거 → 트랙 전체 그리기 1회 감소. 셰이더 3개 → 2개 |
| 강수 | 강수 덮개 1장 유지, 한 셰이더에서 3층 샘플 + 트랙 알파 마스크 = 텍스처 읽기 4회 | 읽기 +1회, 대신 필터 면 제거로 전체 fill은 감소 |
| 타일 배율 | 반복 횟수가 아니라 **텍셀:화면 px 비율**로 지정, 가로·세로 같은 비율(정사각 텍셀) | 늘어짐 제거 |
| 층 순서 | 강수는 차량·foreground overlay 위, UI 아래. 가까운 층은 얇고 적어서 차량 가독성 유지 | 차량 아래로 들어가는 문제 해결 |
| 전환 | 컨트롤러·재질을 경기 내내 유지. 색보정 값은 1.5초 동안 이전→다음 날씨로 보간. 강수는 강도 0→1 / 1→0(비↔눈은 0.6초 페이드아웃 → 타일 교체 → 0.9초 페이드인) | 전환 중 생성 없음, 뚝 바뀜 제거 |
| 사전 준비 | 경기 준비(SETUP)에서 날씨 타일 4장 로드 + 두 셰이더를 한 번씩 투명하게 그려 준비 | 첫 전환 비용 제거 |
| 매 프레임 CPU | 시간 uniform 1~2개 갱신만(비·눈·폭염 아지랑이일 때만 process) | 동일 |
| 금지 | 강수를 파티클·노드로 구현, 화면 복사, 매 프레임 텍스처/재질 생성, 트랙 프레임(4fps) 교체 때 재질 재생성 | — |

폭염 아지랑이 노이즈는 GPT 아트가 아니라 Codex가 FastNoiseLite(seamless)로 128×128 2채널 PNG를 **오프라인으로 한 번 구워** 커밋한다(런타임 생성 금지).

## 6. 검증 기준

- 격리 확인: Codex가 NightVisionGameProbe처럼 날씨 고정/전환을 재현하는 진입점 제공. 낮 트랙(beach, alps, desert), 밤 트랙(newyork 또는 seoul), 20대 주행.
- 시각: x1에서 날씨 3종이 맑음과 한눈에 구별, 차량·트랙 라인 가림 없음, 반복 격자 안 보임, 비↔눈↔폭염↔맑음 전환이 부드러움.
- 부하: 개선 전/후 같은 fixture에서 평상시 frame·draw call·viewport GPU, **날씨 전환 프레임** 시간. 전환 프레임은 날씨 VFX와 차량 컨텍스트·타이어 VFX 재준비를 구분해 기록.
- 사용자 최종 시각 승인은 Game 격리 화면 녹화 기준.

## 6-1. Codex 사전 확인 결과 (2026-09-29, 소스 조사만)

1 트랙 직접 색보정: 조건부 가능 — 위젯 입력이 원본 알파 기준이므로 **알파는 원본 유지**. 2 강수 층: 조건부 — z값 대신 **월드 위·HUD 아래 별도 CanvasLayer**, 트랙 변환·화면 배율·알파 마스크 동기화 필요. 3 유지·uniform 전환: 가능 — 전환 중 재전환 규칙 필요. 이것만으로 전체 전환 지연이 사라지지는 않음. 4 SETUP 셰이더 준비: 조건부 — 날씨 준비를 별도 작업으로, 투명도 0/숨김으로 완료 판단 금지, 실제 렌더·완료·취소·정리 확인. 5 노이즈 PNG: 가능. 6 개선 전 측정: 가능(`WeatherTransitionProbe.gd`, `NightVisionGameProbe.gd` 재사용). 최종 인계에 좌표계·알파 보존·재전환 규칙·렌더 준비 완료 조건을 명시하기로 함. 구현 전 추가 질의(월드·HUD가 같은 Canvas라 CanvasLayer가 HUD를 덮음)에 따라 강수는 **TrackController 아래 절대 z 4000**(차량·foreground 위, 이름표 4095·HUD 4096 아래)을 1순위로 정정, 월드 CanvasLayer 분리는 조건 불충족 시 대안 → [최종 인계](../../handoffs/2026-09-29-weather-codex-handoff.md).
