# 비·눈 물보라 잔류(B) + 타이어 자국 개선(C) — 설계

> **상태 (2026-09-30):** C(MultiMesh 타이어 자국)는 Game에 적용·유지. B의 둥근 puff 월드 잔류 표현은 사용자 피드백으로 **폐기**되고 wake 띠로 대체됨 → 최종 기록은 `2026-09-30-weather-wake-and-contacts-design.md`. Game의 `VEHICLE_FOLLOW_WORLD_TRAIL` PARTICLE 엔진 지원(v0.2-35.30.18)은 향후 효과용으로 남김. 이 문서의 뒷바퀴 접점 (±41, +117)은 잘못된 값.

2026-09-30 · 설계·Studio 제작·리소스 검수: Claude · 아트: GPT · Game 구현: Codex · 승인: 사용자(B+C 통합 진행 승인 2026-09-30)

## 0. 배경과 범위

- 선행: 비·눈 타이어 VFX 교체(`2026-09-30-weather-tire-vfx-design.md`) Game 적용 완료. 사용자 질문 "폭우·폭설에서 자연스러운가?"에 대한 결론: **아니다** — 판이 차에 고정되어 코너에서 함께 돌고(배기·분사처럼 보임), 두 줄기 V가 짧고 어두우며, 노면 흔적이 없다.
- **B**: 바퀴 뒤 물보라·눈보라 조각이 **생성 위치의 월드에 남아** 퍼지며 사라지게 → 코너에서 주행선 따라 휘는 꼬리.
- **C**: Codex가 코드로 만든 코너 타이어 자국(`scripts/effects/TireMarkLayer.gd`)의 **품질·부하 개선 + 날씨별 표현**.
- 유지: 타이어 자국 **발생 조건**(`CarAgent._update_visual_effects`: 코너 구간 또는 슬립, 유효 속도 ≥ 코너 속도×0.55, 0.08s 간격, `runtime_suppress_tire_marks`), 날씨 판정·주행 로직, 트랙 날씨 표현(승인 완료).

## 1. 현재 상태 (Game 읽기 전용 확인)

### 1-1. 타이어 자국 `TireMarkLayer`

| 항목 | 현재 | 문제 |
|---|---|---|
| 형태 | 자국 1개 = 차량 **중심** 위치 ± 8px(`TIRE_GAP` 16 × 배율)에 길이 18px·폭 2px 직선 2개, `draw_line` antialiased, 색 (0.03,0.025,0.02) α 0.30×strength×slip | 0.08s마다 끊긴 짧은 선 → 점선·바느질 자국. 고무 질감 없음. 뒷바퀴가 아닌 차 중심 |
| 소멸 | 시간 감쇠 없음. `MAX_MARKS` 240 초과 시 가장 오래된 것 **즉시 삭제** | 톡 사라짐. 코너 차량이 많을수록 수명 짧아짐 |
| 날씨 | 동일 색 | 비·눈에서도 마른 고무 자국 |
| 부하 | `add_tire_mark()`마다 `queue_redraw()` → `_draw()`가 Dictionary 240개 순회, AA 선 480개 재생성. 20대 × 12.5회/s 코너 → **사실상 매 프레임 전체 재구축** | 코너 구간 CPU가 차량 수에 비례 |

### 1-2. 월드 잔류 파티클

- Studio 계약에는 이미 `VEHICLE_FOLLOW_WORLD_TRAIL`이 있다: 생성 시점에 차량 변환으로 **월드 좌표를 한 번 캡처**하고 이후 차량을 따라가지 않음(`VFX_EXPORT_PACKAGE_V1.md`, `VFX_SCHEMA_V1.md`, Studio preview `vfx_particle_layer_renderer.gd`가 PARTICLE에 대해 구현).
- Game은 `VfxRendererFactory.preflight_layer`에서 `VEHICLE_LOCAL`이 아니면 `unsupported_space_mode`로 거부. → **B는 새 계약이 아니라 기존 계약의 Game 구현**.

## 2. 연출

### 2-1. B — 물보라·눈보라 잔류

| | 비 | 눈 |
|---|---|---|
| 차에 붙은 판(현재 package의 LOOP 판) | 유지하되 길이 ×0.5 수준으로 **짧게**(바퀴 바로 뒤 뿌리 역할). 투명도 상향 | 같음 |
| 월드 잔류 조각(신규 PARTICLE, `VEHICLE_FOLLOW_WORLD_TRAIL`) | 뒷바퀴 축에서 차 1대당 동시 4~5개, 수명 0.7~0.9s. 생성 후 월드에 남아 **크기 1→2.2배로 부풀며** 알파 0.55→0, 약간 뒤·옆으로 흩어짐(0~40 px/s) | 수명 1.0~1.3s, 크기 1→2.6배, 알파 0.7→0, 흰색. 더 오래 머묾 |
| 보조(현재) | 빗방울 파티클 유지 또는 잔류 조각으로 대체(시안에서 결정) | 눈 덩어리 유지 |
| 판독성 | 뒤차를 가리지 않게 조각 알파 상한 0.55, 차량보다 아래(`UNDER_VEHICLE` 의미) | 상한 0.7 |

차가 달리면 조각이 제자리에 남으므로 **길이 = 속도 × 수명**으로 자연히 늘어나고, 코너에서는 주행선을 따라 휜다. 멈추면 조각이 차 뒤에 쌓이지 않도록 발생을 `speed_normalized`로 줄이는 것이 이상적이나 PARTICLE은 modulation 미지원 → 저속 잔존은 수명·개수로 억제(아래 3-3).

### 2-2. C — 타이어 자국

| | 맑음 | 폭염 | 비 | 눈 |
|---|---|---|---|---|
| 의미 | 고무 자국 | 진한 고무 자국 | 바퀴가 물을 밀어낸 어둡고 번들거리는 줄 | 회색 진눈깨비·다져진 눈 줄 |
| 색(초안) | (0.04,0.035,0.03) α 0.35 | α 0.45 | (0.02,0.03,0.05) α 0.30 + 가운데 약한 밝은 결 | (0.78,0.80,0.84) α 0.28 |
| 수명(초안 → 4-1에서 6/7/3/5s로 수정) | 8s | 10s | 3s(물이 다시 덮음) | 6s |
| 소멸 | 수명 뒤 40% 구간에서 부드럽게 α→0 | 같음 | 같음 | 같음 |

공통 형태:
- **뒷바퀴 두 위치**에서(차량 중심이 아니라 뒷바퀴 축, 좌우 간격은 차량 스프라이트 폭 기반 — Codex가 차종별 값 확인), 바퀴별 **직전 기록 위치 → 현재 위치**를 잇는 조각으로 연속 곡선.
- 고무 자국 텍스처(GPT 1장)를 길이 방향으로 이어 붙임(UV 연속).
- 슬립 시 폭·알파 배율은 현재 값 유지(`slip_tire_mark_*`).
- 날씨 전환 시 이미 남은 자국은 원래 색으로 자연 소멸, 새 자국부터 새 날씨 표현.

## 3. 구조와 부하 (Codex 구현 제안)

### 3-1. C — 렌더링

- `TireMarkLayer`를 **MultiMeshInstance2D 1개**(사각형 메시 + 고무 텍스처)로 교체. 인스턴스당 변환(조각 시작~끝), 색(날씨), custom data(생성 시각, 강도).
- 셰이더가 `TIME`(또는 경기 시계 uniform) − 생성 시각으로 감쇠 계산 → **매 프레임 CPU 작업 없음**, draw call 1.
- 추가는 링 버퍼 인덱스 1칸 갱신(O(1)). 상한은 안전장치: 수명 × 최대 발생률 기준(예: 20대 × 바퀴 2 × 12.5/s × 8s ≈ 4000 → 실제 코너 비율 고려해 1024~2048에서 Codex 판단).
- `clear_marks()`/트랙 교체/레이스 정리 시 `visible_instance_count = 0`.
- 공개 API `add_tire_mark(...)`와 `get_mark_count()`는 유지(호출부 변경 최소화). 바퀴별 직전 위치는 호출 측(차량) 또는 레이어가 차량 ID별로 보관.

### 3-2. B — 월드 잔류 PARTICLE (Game 확장)

- PARTICLE 레이어의 `space_mode: VEHICLE_FOLLOW_WORLD_TRAIL` 지원:
  - 생성: 이미터 위치·방향·속도를 **생성 순간** 차량 변환(위치·회전·게임 배율)으로 월드 좌표로 변환.
  - 이후: 차량 transform의 영향을 받지 않음. 월드 컨테이너(타이어 자국 위, 차량 아래 — 4-1 순서)의 자식으로 그림.
  - 수명·크기·알파 곡선은 기존 PARTICLE 계약 그대로. 현재 CPU 호환 백엔드(스프라이트 풀)를 월드 컨테이너에 두는 방식이면 renderer 로직 재사용 가능.
  - 소진·강제 정리: 효과 종료 시 새 발생 중단, 남은 조각은 월드에서 수명대로 소진(`is_drained`), `force_clear`/레이스 정리/차량 제거 시 즉시 제거.
- 부하 목표: 차 1대당 조각 최대 5 + 기존 판 1 + 보조 3~4 → 20대 ≈ 180 스프라이트(이전 눈 package 160 수준). 조각은 커다란 부드러운 텍스처라 개수보다 fill이 문제될 수 있음 → 크기 상한을 Codex 측정으로 조정.

### 3-3. 저속 억제

- 발생률이 속도와 무관하므로, 조각 수명을 짧게(비 0.8s) + 최대 개수 작게 + 초기 속도 0에 가깝게. 정지 직전 차 뒤에 조각이 몇 개 머무는 것은 수용. (속도 연동 발생률은 PARTICLE modulation 계약 확장이 필요해 이번 범위 밖.)

### 3-4. Studio 쪽

- Studio preview는 차량 **회전만** 가능하고 이동이 없어 월드 잔류를 제대로 볼 수 없다. 선택지:
  1. Game 격리 진입점(Codex)에서 최종 판단(권장, Studio 변경 없음).
  2. Studio preview에 "가상 주행 속도" 이동 추가(Studio 공통 기능 확장 — 필요하면 별도 승인).
