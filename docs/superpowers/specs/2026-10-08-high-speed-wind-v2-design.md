# 고속 주행 바람(High-Speed Wind) v2 설계

2026-10-08. 사용자 요청: 현재 바람이 나쁘지 않지만 더 좋게. 개선안 1~4 모두 진행 승인.
대상: `driving.high_speed_wind` (ID 유지). Game 연결(`HighSpeedWindVfxIntegrationController`)은 그대로다.

## 1. 측정 결과 (2026-10-08, 20대·뉴욕·비, 경기 21~29초)

- 바람은 차량-표본의 약 34%에서만 켜진다. 켜진 동안 71%가 강도 0.25~0.5, 0.75 초과는 5%.
- 켜짐/꺼짐 전환 간격의 25~30%가 0.5초 미만(1~2프레임 포함). 전부 `speed_threshold`. 전환마다 START/END가 다시 재생된다.
- package가 `runtime_inputs`를 선언하지 않아 속도가 올라가도 모양이 같다.
- 게임 크기에서 차 뒤 중앙에 얇은 선 1~2개만 보이고 차체 옆으로 흐르는 표현이 없다.

## 3. 속도 단계

바람은 속도 70% 이상에서 켜진다. `speed_normalized`는 속도 / 유효 최고 속도(0~1)다.

| 구간 | 속도 | 보이는 것 |
| --- | --- | --- |
| 기본 | 70~77% | 뒤 줄기 3겹(파티클)과 아주 옅은 옆 선(속도 이득 0.1~0.4, 길이 ×0.8~0.9). |
| 중간 | 77~88% | 옆 선이 점점 진해지고 길어짐(속도 이득 0.4~0.8, 길이 ×0.9~1.05). |
| 최고속 | 88~100% | 옆 선이 가장 진하고 길다(속도 이득 1.0, 길이 ×1.15). |
| 부스터 | `boost_active` 1 | 옆 선 투명도 ×1.3, 길이 ×1.15 추가 (Game이 0.08초 올림·0.3초 내림으로 부드럽게 공급). |

파티클 레이어는 속도 연동이 안 된다. Studio 스키마와 Game 파티클 렌더러 모두 투명도·크기 modulation을 TEXTURED_SPRITE에만 허용한다. 그래서 기존 파티클 3겹은 그대로 두고, 속도에 반응하는 부분은 TEXTURED_SPRITE 레이어로 얹는다. Game 코드 변경 없이 기존 modulation 기능만 쓴다.

## 4. 옆 흐름 선 설계

- 레이어: LOOP의 TEXTURED_SPRITE 4개(좌 2, 우 2), `UNDER_VEHICLE`, ALPHA.
- 위치: x = ±122, 두 번째 줄 ±136 (차체 옆 끝 ±96, 타이어 ±102 바깥). 차 폭은 전 차종 공통이라 차종별 보정 없음.
- 움직임: `LINEAR_PHASE`(톱니파) → `TRANSFORM_OFFSET_Y`로 y −150 → +330을 흐른다. 같은 주파수의 `OSCILLATOR`(위상 −90°)로 투명도 포락선 `sin²`를 만들어 주기 시작과 끝에서 0이 된다. 팝인 없이 나타났다 사라진다.
- 모임: `TRANSFORM_OFFSET_X`를 같은 톱니파로 안쪽(좌 +, 우 −)으로 14px 이동시켜 꼬리 쪽에서 차 뒤로 모이는 유선을 만든다.
- 줄마다 주파수를 다르게 한다(1.60~2.15 Hz). 소스 시간이 effect 전체 경과 시간이라 서로 위상이 어긋나 불규칙하게 보인다.
- 투명도 = `opacity` × 포락선 × 속도 이득 × 부스터 이득. 속도 이득은 `speed_normalized` 0.70→0.96 을 0.10→1로 매핑한다(작은 바닥값만 둔다).
- START/END: 옆 선은 LOOP에만 둔다. END로 넘어갈 때 선이 갑자기 사라지지 않도록 속도 이득 바닥값과 별개로 `speed_cutoff` 바인딩(`speed_normalized` 0.62 → 0.70을 0 → 1로, MULTIPLY)을 둬서 70% 아래에서는 62%까지 투명도가 0으로 줄어든다(히스테리시스 0.35초 동안 속도가 내려가므로 END 시점에는 거의 0).

Wind Racer(청백색 바람 다발 A/B)와 형태가 겹치지 않도록 옆 선은 가늘고 적게(한쪽 최대 2줄, 투명도 낮게) 유지한다. 두 효과가 동시에 켜져도 Wind Racer가 더 풍성해야 한다.

## 5-1. 최종 값

| 레이어 | 텍스처 | 위치 x / y | 회전 | 크기 | 투명도 | 중요도 | 주파수 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `loop.flank_l1` / `r1` | flow_a | ∓122 / 90 | ∓2° | 0.8 × 1.1 | 0.66 | DETAIL | 1.60 / 1.75 Hz |
| `loop.flank_l2` / `r2` | flow_b | ∓136 / 70 | ∓2° | 0.8 × 1.1 | 0.55 | EXTRA | 1.95 / 2.15 Hz |

- 이동: 중심이 y −150 → +330(source px)으로 흐르고 x는 안쪽으로 14px 이동.
- 투명도 포락선: `sin²` 입력 −0.75 → 0.35를 0 → 1로 매핑한다.
- 속도 이득: `speed_normalized` 0.70 → 0.96을 0.10 → 1로, 길이 ×0.8 → ×1.15. 70% 아래 감소: `speed_cutoff` 0.62 → 0.70을 0 → 1로. 부스터: 투명도 ×1 → ×1.2, 길이 ×1 → ×1.1.
- LOD: HIGH 7층(파티클 3 + 스프라이트 4), MEDIUM 4층(Main, Fine, DETAIL 스프라이트 2), LOW 1층(Main). 스프라이트는 연속 파티클 용량에 더해지지 않는다.

## 5-2. 1차 사용자 피드백 반영 (2026-10-09, 과해서 5-3에서 되돌림)

사용자가 Game 녹화(맑은 낮 해변)를 보고 "뒷선은 괜찮은데 옆선은 잘 안 보인다"고 했다. 원인: 최종 텍스처가 프로토타입 때보다 가늘고(폭 약 2px) 투명도도 낮췄으며(0.9→0.6), 선 중심이 차체 가장자리와 겹쳐 절반이 가려졌고, 영상 압축이 가는 선을 더 뭉갰다. 조정: 폭 ×1.7(0.7→1.2), 투명도 0.6/0.5 → 0.92/0.8, 위치를 바깥으로(118/132 → 128/146), 꼬리 쪽 모임 24 → 12px, 주파수를 낮춰 선이 더 오래 보이게(1.85~2.60 → 1.25~1.80 Hz), 포락선 최대 구간을 넓힘, 속도 이득에 바닥값 0.35를 둬 70% 속도에서도 보이게 함. Game 실측(clear, beach, 20대): 옆선 4개 투명도가 0~1.0 사이를 돌고 길이 ×1.0~1.7로 변하며 낮 장면에서 흰 줄로 보인다.

## 5-3. 2차 사용자 피드백 반영 (2026-10-09)

5-2의 보정(폭 ×1.7, 투명도 0.92/0.8 등)은 **과했다.** 사용자 확인: "이전 상태에서 아주 약간만 올리려던 건데 너무 인위적이고 가짜 같다." 평행한 흰 막대처럼 보였다. 값을 이전(1차 적용값)에서 약 10~30%만 올린 현재 값(5-1)으로 되돌렸다. 일반 속도(0.8)에서 옆선 투명도 최대는 이전 0.23 → 0.29, 최고속은 0.60 → 0.66이고 폭은 ×1.14다. Studio 프리뷰(200%)와 Game 맑은 낮 비치 서킷 캡처에서 뒤 줄기와 비슷한 세기로 확인했다. 교훈: 얇은 보조 선을 보강할 때는 한 번에 한 가지만, 그리고 이전 대비 10~30% 단위로 올린다.
